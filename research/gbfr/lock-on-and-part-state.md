# 록온 대상 식별과 부위 파괴 상태

대상 빌드와 근거 분류는 [연구 개요](README.md)를 따른다. 핵심은 록온 선택 번호, 실제 피해를 받는 부위, 내구도 상태 및 파괴 완료 처리가 별도 관계라는 점이다. 하나의 공통 부위 HP 배열을 모든 보스에 적용할 근거는 없다.

## 조작 캐릭터와 대상의 식별

**실행 관찰 및 구현 정책:** AI 동료를 포함하는 플레이어 등록 목록의 첫 항목이 조작 캐릭터라는 가정은 사용할 수 없다. 공개 구현은 엔진의 로컬 조작 actor와 일치하는 항목을 찾고, 해당 항목의 소유자 체인이 로컬 scene으로 돌아오는지 검사한다. 오프라인의 AI 동료 포함 사례에 관찰 근거가 있으나 온라인의 소유권 관계는 미검증이다.

이 빌드에서 구현이 읽는 전역은 다음과 같다. 주소는 모두 RVA다.

- 로컬 scene handle: `0x7035CA0`의 ID, `0x7035CA8`의 scene 포인터, `0x7035CB0`의 stamp.
- 로컬 조작 actor: `0x7035D00`.
- scene manager: `0x7020988`. manager의 `+0x20`은 scene 슬롯 배열, `+0x48`은 stamp 배열을 가리킨다.
- 플레이어 등록 목록 범위: `0x7362690..0x7362698`.
- 등록 항목의 `+0x230`을 조작 actor와 대조하고 소유자 연결을 검증한다. 일치 항목이 없거나 둘 이상이면 읽기를 거부한다.
- 검증한 항목의 `+0x108`에서 현재 대상 scene을, `+0x118`에서 선택 ID를 읽는다.

핸들 검증은 ID만 비교하지 않는다. `(ID-1)`번 슬롯의 scene과 stamp, scene 자체의 `+0x38` ID·`+0x40` self·`+0x48` stamp·`+0x70` actor를 함께 비교한다. 읽기 후에 대상과 원본 연결이 바뀌지 않았는지도 다시 검사한다.

**해석:** 이는 주소 재사용이나 읽는 도중의 대상 교체를 거부하기 위한 관계 검증이다. 모든 필드가 원자적으로 고정된 스냅샷을 얻었다는 보장은 아니다. world 또는 표시 generation이 바뀌면 기존 초기값 증명과 표시 상태를 무효화하는 것은 모드의 정책이다.

[NativeStateReader.TryReadWorld](https://github.com/czhskr/GBFR-Modding/blob/70f96f8611cf9762bc9a6d7c42a590336ed3d478/Part-Break-Indicator/NativeStateReader.cs#L21)와 `TryReadSnapshots`가 이 관계를 구현한다. 제품의 상태 리더는 메모리 읽기 경로이며, 각 공격의 피해 콜백을 상시 후킹해 내구도를 자체 누적하는 방식이 아니다.

## 선택 번호, 상태 인덱스와 피격 번호

**정적 확인 및 실행 관찰:** lock ID, lock vector의 행 번호, 상태 배열 인덱스, collision 식별자, damage mask는 같은 번호 체계가 아니다.

- 악어형 `Em0500/0501/0502`에서 선택 ID `2628`, `9`, `13`은 상태 인덱스 `0`, `1`, `2`에 연결된다.
- Pyet-A의 선택 `772`는 상태 `6`, 선택 `901`은 상태 `0`에 연결된다.
- 사족 후라칸의 선택 `5`는 상태 `8`에 연결되는 정적 경로와 선택 표본이 있다. 정적 damage mask `0x1`과의 관계를 그 머리 내구도의 실제 차감 증명으로 대체할 수는 없다.

록온을 유지한 채 다른 부위의 상태가 감소할 수 있다. 원거리 공격이나 범위 공격의 화면상 도달, 실제 incoming-hit 기록, 해당 상태의 차감은 구별해야 한다. 여러 collision 행이 하나의 상태에 합류하는 경우도 있다.

actor의 `+0x788..+0x790`에서 읽는 lock vector는 이 구현에서 48바이트 행으로 다룬다. 행의 선택 ID와 활성 byte `+0x29`는 한시적으로 선택 가능한 부위를 확인하는 데 사용한다. 같은 번호가 모든 타입에서 고유하다는 가정도 하지 않는다. 부위별로 필요한 행과 연결을 검증한다.

### `-1`은 타입과 대상 관계를 함께 확인해야 한다

**연구 관찰:** Excavallion의 거골 리액터 `Em7401`에서는 유효한 대상과 유일한 활성 lock 행의 ID가 모두 `-1`이었다. stamped 부모 핸들은 정확한 `Em7400` 개체로 연결됐다. 따라서 선택 번호 하나만 보고 모든 타입에서 록온 해제라고 결론 내릴 수 없다.

이 리액터의 자체 ExHp는 `actor+0x160`의 current qword와 `actor+0x168`의 maximum qword를 읽는 경로와 일치했다. 동일 개체의 자연 공격 전후 값은 `1,602,072 → 1,543,653`이었고 maximum은 `1,602,072`를 유지했다. 파괴 완료·리셋·초기화 인수의 근원은 이 표본에서 관찰하지 않았다.

이는 공개 모드가 지원하는 일반 부위 배열의 예가 아니라 별도 연구 관찰이다. 기본 체력바 자체가 파괴 진행도를 표시하는 대상이어서 추가 모드 표시는 보류돼 있다. 다른 Excavallion 자식 타입 전체의 UI·파괴 의미까지 이 표본으로 확장하지 않는다.

## 현재값 0과 파괴 완료는 별도 상태일 수 있다

**정적 확인 및 실행 관찰:** 보스에 따라 파괴 처리 이력이나 processed byte가 따로 존재한다. 아주 작은 양수 float가 남는 경우, 현재값이 먼저 0이 되고 처리 마커가 뒤따르는 경우, 보호 조건에서 1이 유지되는 경우, 초기화가 0을 쓰는 경우를 구별해야 한다.

**구현 정책:** 공개 구현은 다음처럼 타입별 경로를 사용한다.

- **악어형·드래곤·Behemoth:** 현재값과 파괴 이력을 분리한다. 정상 모드의 초기값 출처와 미파괴 현재값 일치로 확인한 증명을 보존한다. 파라미터·stamp·파괴 상태 등 관계가 바뀌면 기존 증명을 재평가한다. 최대값 출처가 미확정인 대체 모드 경로는 아이콘만 표시한다.
- **Pyet-A:** 일곱 선택/상태의 연결을 다룬다. 저장된 초기값을 해당 파라미터 출처와 대조하며, 현재값과 처리 이력을 함께 사용한다. 이력 없는 0을 바로 파괴 아이콘으로 바꾸지 않는다. 대표 꼬리의 자연 파괴 관찰이 모든 부위·모드의 파괴와 재생 검증을 뜻하지는 않는다.
- **후라칸:** 사족형과 인간형의 레이아웃을 분리한다. 현재값·초기값·파괴 플래그를 사용하며 임시 록온의 가용성도 검사한다. 인간형의 갑옷 파괴/복구와 사족 다리의 파괴/복구 관찰이 있다. 사족 팔의 피해 후 수치와 복구 표본도 있으나 모든 팔의 선택 중 파괴 화면을 확인한 것은 아니다. 사족 머리는 선택/정적 연결 표본과 공개 코드 경로까지이며 실제 적용 피해·파괴·재생·후보 UI는 미검증이다.
- **타유타르:** 다리의 정확한 최대값 출처가 미확정이므로 다리는 상태 아이콘만 표시한다. 헤드 유닛은 별도 현재값·초기값 출처·처리 마커를 결합한다. 0만으로 헤드 파괴 완료를 판정하지 않는다.
- **프로토 바하무트:** 선택 `2048`의 상태 정수와 같은 소유자의 초기값·처리 이력을 결합한다. 보호 조건에서 1에 머무를 수 있으며, 초기화에 쓰이는 0과 처리 파괴를 구별한다. 처리 파괴 전후의 지속 상태와 실제 파괴 표시 관찰은 있으나 모든 중간 프레임의 정확한 순서를 측정한 것은 아니다.
- **앙그라 마이뉴:** 하나의 머리 선택 `5`에 두 뿔 상태가 연결된다. 모드 0/1의 상태 0/1 쌍과 모드 2의 상태 2/3 쌍을 구별한다. 한쪽의 피해·파괴가 다른 쪽으로 합산되지 않도록 읽는다. 후반 형태의 양쪽 처리 파괴와 최종 표시는 관찰했지만 모든 개별 타격 순간의 좌우 화면 변화까지 확인한 것은 아니다.
- **볼칸불라:** 부모/자식 핸들·부위 정의·모델 연결을 검증한 shell 개체의 float 현재/초기값을 읽는다. 이 경로에서 0의 파괴 의미는 해당 native 처리 경로와 함께 해석한다. 두 팔의 파괴 후 잠수·부상에 따른 복구 관찰이 있다. 별도 특수 선택 `3840`·`282`는 독립 피해·0 전이·활성 해제까지 관찰했으며, 재활성 후 초기값과 표시 복원은 미검증이다.

타입별 선택 매핑과 표시 판정은 [PartStatePolicy](https://github.com/czhskr/GBFR-Modding/blob/70f96f8611cf9762bc9a6d7c42a590336ed3d478/Part-Break-Indicator/PartStatePolicy.cs)에, native 소유자·필드·초기값 검증은 [NativeStateReader](https://github.com/czhskr/GBFR-Modding/blob/70f96f8611cf9762bc9a6d7c42a590336ed3d478/Part-Break-Indicator/NativeStateReader.cs)에 있다. 이 열거는 전체 게임의 부위파괴 가능 보스 목록이 아니다.

## 초기값 증명과 재생

관찰을 시작한 시점의 current가 곧 maximum이라는 보장은 없다. 이미 다른 공격이 들어갔거나 난이도·형태·보호 조건·다른 모드의 영향으로 값이 다를 수 있다. 파라미터 안에 HP처럼 보이는 값이 있다는 사실만으로 런타임의 해당 부위 분모라고 확정할 수도 없다.

**구현 정책:** 검증된 양수 초기값이 있는 경우에만 `current / initial`을 백분율로 사용한다. 표시에서는 소수부를 버리고, current가 양수인데 정수 계산이 0이 되는 경우 최소 1%를 사용한다. 실제 처리 완료 상태가 있으면 백분율을 숨긴다. 이 반올림·숨김 규칙은 게임의 내부 내구도 정의와 별개의 UI 정책이다.

초기값 증명은 현재 world/generation, scene, actor, ID, stamp, 타입과 파라미터의 관계에 결속한다. 같은 전투의 다른 몬스터로 전환했을 때 하나의 전역 분모를 재사용하지 않는다. 주소가 같더라도 stamp나 상태 관계가 달라지면 다른 인스턴스로 취급해야 한다.

재생하는 부위에서는 한 번 파괴됐다는 과거 이력만 영구적으로 기억하면 오류가 난다. 현재값 복원과 processed 플래그 초기화, 한시적인 lock 활성화도 각각 확인해야 한다. 재생된 부위와 파괴된 채 남은 부위를 같은 규칙으로 취급하지 않는다.

## 미해결 범위와 업데이트 후 검증

골렘·바하무트 얼터의 물리 상태와 직접 록온 부위 연결은 미해결이다. 이를 부위파괴 불가라는 결론으로 바꾸지 않는다. 파라미터·보상 표·factory 별칭의 항목 수만으로 실제 접근 가능한 보스와 파괴 부위 전체가 확정되는 것도 아니다.

현재 모드의 표시 범위는 직접 록온할 수 있는 부위다. 직접 선택되지 않는 몸통 등도 게임 내부에서 파괴될 수 있으므로, 표시 범위와 게임의 모든 파괴 가능 상태를 구별한다.

업데이트 뒤에는 로컬 actor의 writer/consumer와 소유자 체인, handle/stamp의 재사용 규칙, 정확한 파생 타입, 부모/자식 관계, lock 가용성·상태 매핑, 난이도/형태별 초기화 출처, 파괴 처리·보호·재생 경로를 다시 확인해야 한다. 공통 destructor에서 관찰한 기저 타입 배치를 모든 파생 보스의 상태 오프셋으로 일반화하지 않는다.
